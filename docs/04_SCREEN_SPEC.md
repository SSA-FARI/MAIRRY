# 04. 화면 명세

## 디자인 방향

- 데스크톱 우선 반응형 금융 대시보드
- 흰색·중성 배경에 한 가지 포인트 컬러 사용
- 큰 숫자, 짧은 라벨, 충분한 여백으로 자산 정보를 빠르게 인지
- 금액은 우측 정렬하고 천 단위 구분 및 원 단위를 통일
- 위험은 색상만이 아니라 아이콘·문구를 함께 사용
- 화면마다 가장 중요한 행동 버튼은 하나만 강조

## 공통 레이아웃

- 좌측 내비게이션: 대시보드 / 계약 / AI 플래너
- 상단: 서비스명, 결혼일까지 남은 기간, 문서 업로드 버튼
- 본문 최대 너비를 제한해 카드가 과도하게 늘어나지 않도록 구성
- 모바일에서는 내비게이션을 하단 탭 또는 메뉴로 전환

## S01. 초기 설정

- 목적: 대시보드 계산에 필요한 최소 정보 입력
- 입력: 결혼 예정일, 현재 가용자금
- 버튼: 계획 시작하기
- 검증: 미래 날짜, 0원 이상 숫자
- 성공: 대시보드로 이동

## S02. 대시보드

목적: 자산과 확정 지출을 한눈에 파악

### 상단 요약 카드

1. 현재 가용자금
2. 남은 확정지출
3. 예상 잔액
4. 가장 가까운 결제

예상 잔액이 음수면 부족액과 경고 문구를 표시한다.

### 본문

- 좌측 넓은 영역: 지급 타임라인
- 우측 영역: 계약 현황, 확인 필요 문서, 빠른 시뮬레이션
- 빈 상태: 계약서 업로드를 유도하는 설명과 버튼

### 주요 행동

- 계약서 업로드
- 타임라인 항목 선택 → 계약 상세
- 추가지출 계산 → 시뮬레이션 패널

## S03. 계약서 업로드

- Drag & Drop 및 파일 선택
- 허용 형식과 최대 용량 표시
- 상태: 대기 / 업로드 중 / 분석 중 / 실패
- 성공 시 검수 화면으로 자동 이동

## S04. 추출 결과 검수

- 데스크톱: 좌측 원문 미리보기, 우측 편집 폼
- 모바일: 원문/입력 탭 전환
- 필드: 업체명, 총액, 지급항목, 지급일, 상태, 취소조건
- 각 필드 아래 근거 문장 표시
- 경고가 있는 필드는 확인 필요 배지 표시
- 버튼: 계약 확정, 나중에 확인
- 확정 전에는 자금 계산에 반영되지 않음을 명시

## S05. 계약 목록·상세

- 목록: 업체명, 총액, 다음 지급일, 검토 상태
- 상세: 계약 요약, 지급항목, 취소조건, 근거, 원문
- 상세 주요 행동: 계약 수정, 계약 삭제
- 지급항목별 상태 선택: 미지급 / 지급 완료 / 확인 필요. 변경 즉시 저장하며 진행·실패 상태를 표시
- 수정: 검수 화면과 같은 입력·검증을 사용하고 저장 성공 후 상세로 이동
- 삭제: 확인 대화상자에서 영향 범위를 안내하고 성공 후 계약 목록으로 이동
- 계약 목록은 확정 계약만 표시한다. 검토 필요 문서는 대시보드와 문서 검수 흐름에서 표시한다.

## S06. 추가지출 시뮬레이션

- 입력: 항목명, 추가 금액
- 결과: 기존 예상 잔액 / 변경 예상 잔액 / 부족 여부
- 시뮬레이션 결과는 저장하지 않는다.

## S07. AI 플래너

- 추천 질문 3~4개 제공
- 사용자 질문과 답변을 대화형으로 표시
- 답변 아래 계약 근거 또는 계산 기준 표시
- 근거 선택 시 계약 상세로 이동

## 공통 상태

| 상태 | 처리 |
|---|---|
| Loading | 스켈레톤 또는 진행 문구 |
| Empty | 다음 행동을 설명하는 CTA |
| Error | 원인 요약, 재시도, 입력값 유지 |
| Success | 토스트 후 갱신된 결과 표시 |
