# 09. 테스트 시나리오

## 테스트 기준 데이터

- 결혼일: 2027-05-15
- 현재 가용자금: 30,000,000원
- 계약 총액: 23,000,000원
- 지급 완료 계약금: 3,000,000원
- 미지급 잔금: 20,000,000원
- 잔금일: 2027-04-30
- 추가지출: 3,000,000원

기대 계산:

~~~text
남은 확정지출 = 20,000,000원
예상 잔액 = 30,000,000 - 20,000,000 = 10,000,000원
시뮬레이션 잔액 = 10,000,000 - 3,000,000 = 7,000,000원
부족액 = 0원
~~~

## E2E-01 핵심 골든 패스

1. 결혼일과 가용자금 입력
2. 샘플 웨딩홀 계약서 업로드
3. AI 분석 완료 대기
4. 업체명·총액·지급항목·근거 확인
5. 잔금일을 수정하고 계약 확정
6. 대시보드 확인
7. 추가지출 3,000,000원 시뮬레이션
8. “웨딩홀 잔금일이 언제야?” 질문

통과 조건:

- 확정 전 계약은 대시보드 합계에 포함되지 않는다.
- 확정 후 남은 지출은 20,000,000원, 예상 잔액은 10,000,000원이다.
- 시뮬레이션 잔액은 7,000,000원이다.
- AI 답변은 2027-04-30과 계약 근거를 포함한다.
- 전체 흐름에서 치명적 오류나 막힌 화면이 없다.

## AI 샘플 평가

각 샘플에서 다음 필드를 기대값과 비교한다.

- documentType
- company
- totalPrice
- payments.name
- payments.amount
- payments.dueDate
- payments.status
- sourceText

치명 오류:

- 존재하지 않는 금액 또는 날짜 생성
- 계약금과 잔금 뒤바꿈
- 지급 완료 항목을 미지급으로 확정
- 근거와 추출값 불일치

치명 오류가 있으면 사용자 확정 단계에서 확인 필요로 표시하거나 분석 실패로 처리한다.

## 대화 Tool 검증

Chat 테스트에서는 최종 문장만 비교하지 않고 호출 기록을 함께 검증한다.

- 금액 질문이 지정된 finance Tool을 호출했는가?
- 일정 질문이 getUpcomingPayments를 호출했는가?
- Tool에 전달된 amount, 기간, contractId가 사용자 질문과 일치하는가?
- AI 답변의 모든 금액·날짜가 ToolResult와 일치하는가?
- NOT_FOUND·INSUFFICIENT_DATA·TOOL_ERROR에서 추측한 값이 없는가?
- 동일한 확정 데이터와 인자에서 서버 계산 결과가 항상 같은가?

### CHAT-06 기준 예시

~~~text
질문: 가전 비용 300만 원을 추가하면 괜찮아?
필수 호출: simulateAdditionalExpense(name="가전 비용", amount=3000000)
Tool 결과: simulatedExpectedBalance=7000000, shortageAmount=0
답변 조건: 7,000,000원과 부족 없음 포함, 다른 금액 생성 금지
~~~

### CHAT-04 기준 예시

~~~text
질문: 가장 가까운 잔금일은 언제야?
필수 호출: getUpcomingPayments(limit=1)
Tool 결과: dueDate=2027-04-30, amount=20000000
답변 조건: 날짜·금액·계약명이 Tool 결과와 일치
~~~

## 대시보드 확인

- 상단에 현재 가용자금, 남은 확정지출, 예상 잔액, 가까운 결제가 보인다.
- 금액 표기가 모든 카드와 표에서 동일하다.
- 예상 잔액이 음수면 부족액과 경고 문구가 표시된다.
- 타임라인 항목 선택 시 해당 계약 상세로 이동한다.
- 계약이 없을 때 업로드 CTA가 보인다.
- 모바일에서도 핵심 카드와 주요 버튼을 사용할 수 있다.

## API·보안 확인

- 잘못된 상태의 확정 요청은 409를 반환한다.
- 다른 사용자 ID의 문서·계약은 조회되지 않는다.
- API 오류는 공통 error 형식을 따른다.
- 서버 로그에 계약 원문과 비밀키가 출력되지 않는다.
- 객체 스토리지 파일은 공개 접근되지 않는다.
